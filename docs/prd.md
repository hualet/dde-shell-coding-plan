# dde-shell Coding Plan 额度插件 PRD

## 1. 背景

开发者同时订阅多个 AI Coding Plan 后，额度分散在不同控制台或客户端中，日常很难快速判断哪个服务还可用、哪个服务即将耗尽。本项目希望在 DDE Shell 面板中提供一个轻量插件，集中显示 Coding Plan 额度剩余情况，降低切换平台和手动查询成本。

本 PRD 基于当前调研结论制定：Kimi API 与 OpenAI API 侧存在可用的官方查询路径；GLM Coding Plan 可做实验性额度查询；MiniMax 与 ChatGPT/Codex 订阅额度公开接口不稳定或未开放，首版不强依赖自动抓取。

## 2. 产品目标

1. 在 DDE Shell 面板中一眼看到已添加 Coding Plan 的剩余额度状态。
2. 点击插件后在弹窗中查看各平台额度详情、刷新时间和异常状态。
3. 支持多供应商扩展，避免后续新增平台时重写 UI 与数据模型。
4. 对接口不稳定的平台提供降级方案，保证 MVP 可交付。

## 3. 用户与场景

目标用户是使用 deepin/DDE 桌面环境，并同时使用多个 AI 编程服务的开发者。

核心场景：

- 开发前快速判断当前应该使用哪个 Coding Plan。
- 额度接近耗尽时及时切换供应商或充值。
- 某个平台接口失效时，仍能通过手动录入或控制台跳转维护可用信息。

## 4. 范围

### 4.1 MVP 范围

- DDE Shell 面板插件入口。
- 面板上显示多个类似 iOS 电池组件的圆环，每个圆环代表一个已启用平台的额度剩余比例。
- 点击后展示 popup，包含全部已添加订阅的额度详情。
- 支持添加、编辑、删除订阅配置。
- 支持 Kimi、OpenAI、GLM、MiniMax、Codex/ChatGPT 的供应商类型。
- 支持自动查询、手动录入、控制台跳转三种数据来源模式。
- 支持失败状态、上次成功刷新时间、手动刷新。

### 4.2 非目标

- 不在首版实现购买、续费、支付或自动充值。
- 不绕过平台登录验证、不采集浏览器 Cookie。
- 不承诺对未公开接口的平台长期自动同步。
- 不做跨设备云同步。

## 5. 平台支持策略

| 平台 | 首版能力 | 数据来源 | 备注 |
| --- | --- | --- | --- |
| Kimi | 自动查询 | API Key + 官方余额接口 | 作为首个稳定自动同步平台实现 |
| OpenAI API | 自动查询 | API Usage/Costs 相关接口 | 面向 API 账户额度/成本，不等同 ChatGPT 订阅 |
| GLM / 智谱 | 实验性自动查询 | 平台接口或可确认的控制台接口 | 标记 beta，失败时降级为手动录入 |
| MiniMax | 手动录入 + 控制台跳转 | 用户维护 | 暂不依赖不稳定或未公开接口 |
| Codex / ChatGPT | 手动录入 + 控制台跳转 | 用户维护 | 订阅额度无稳定公开查询接口，避免首版返工 |

## 6. 功能需求

### 6.1 面板概览

- 默认展示 1 到 4 个圆环，优先显示用户置顶或额度最低的平台。
- 圆环展示剩余比例、平台标识和状态颜色。
- 状态颜色建议：
  - 正常：剩余比例大于 30%。
  - 预警：剩余比例 10% 到 30%。
  - 危急：剩余比例低于 10%。
  - 异常：最近一次刷新失败或凭证失效。
- 无配置时展示空状态入口，引导添加第一个订阅。

### 6.2 弹窗详情

- 展示所有订阅卡片，包括平台、计划名称、剩余量、总量、周期、剩余比例、上次刷新时间。
- 支持单个平台手动刷新。
- 支持打开平台官网或控制台。
- 自动查询失败时展示错误摘要和降级建议。
- 手动模式下支持快速编辑剩余量和总量。

### 6.3 订阅管理

- 添加订阅时选择平台、数据来源模式、显示名称、计划周期、总额度。
- 自动模式需要填写必要凭证，例如 API Key 或组织 ID。
- 手动模式只需要填写总额度、剩余额度、周期起止时间。
- 支持设置置顶、隐藏、删除。
- 支持为每个平台配置控制台 URL。

### 6.4 数据刷新

- 默认每 30 分钟后台刷新一次自动查询平台。
- 支持用户手动刷新全部或单个平台。
- 刷新失败不覆盖上一次成功数据，记录错误状态与失败时间。
- 对接口限流、网络错误、认证失败进行分类提示。

### 6.5 安全与隐私

- API Key 等敏感信息必须存储在本地安全存储中，不能明文写入普通配置文件。
- 日志中不得输出完整凭证、Cookie 或授权头。
- 所有网络请求仅访问用户配置的平台域名。
- 删除订阅时同步删除对应凭证。

## 7. 数据模型

订阅配置：

- `id`：本地唯一 ID。
- `provider`：供应商类型。
- `display_name`：展示名称。
- `source_type`：`api`、`manual`、`console_link`。
- `plan_name`：计划名称。
- `period_start` / `period_end`：额度周期。
- `total_quota`：总额度。
- `remaining_quota`：剩余额度。
- `unit`：额度单位，例如 tokens、credits、requests、CNY。
- `pinned`：是否优先展示。
- `console_url`：控制台地址。
- `last_success_at`：上次成功刷新时间。
- `last_error`：最近错误摘要。

供应商适配器：

- `provider`：供应商标识。
- `capability`：支持自动查询、手动录入、控制台跳转的能力集合。
- `fetchUsage(config)`：返回标准化额度结果。
- `validateConfig(config)`：验证配置完整性。

## 8. 交互要求

- 面板圆环需要保持紧凑，避免占用过多任务栏空间。
- popup 中的信息密度优先于装饰性设计，适合频繁查看。
- 异常状态要能被快速识别，但不应频繁打扰用户。
- 手动录入入口要足够明显，避免用户误以为所有平台都必须自动接入。

## 9. 验收标准

1. 用户可以添加至少 5 种供应商类型的订阅。
2. Kimi 与 OpenAI API 订阅可以通过配置凭证完成自动刷新。
3. GLM 自动查询失败时可以保留上次成功数据，并切换或回退到手动录入。
4. MiniMax 与 Codex/ChatGPT 可以通过手动录入展示在面板和 popup 中。
5. 面板圆环能够正确反映正常、预警、危急、异常四类状态。
6. 删除订阅后，本地配置和敏感凭证同步清理。
7. README 能链接到本 PRD，后续开发者可以按文档拆分实现任务。

## 10. 里程碑

### M1：插件骨架与静态数据

- 建立 DDE Shell 插件基础结构。
- 实现面板圆环和 popup 静态数据展示。
- 实现本地订阅配置读写。

### M2：供应商适配器与手动模式

- 定义统一适配器接口与标准化额度模型。
- 实现手动录入、控制台跳转。
- 接入 MiniMax、Codex/ChatGPT 的手动展示能力。

### M3：自动查询能力

- 实现 Kimi 自动查询。
- 实现 OpenAI API 用量/成本查询。
- 实现 GLM 实验性查询与失败降级。

### M4：可用性与安全收口

- 接入本地安全存储。
- 完善刷新策略、错误分类、日志脱敏。
- 补齐核心单元测试和插件手工验收清单。

## 11. 风险与对策

- 未公开接口变更：自动查询只依赖官方或可稳定验证的接口；不稳定平台默认手动模式。
- 平台额度单位不统一：统一为“显示单位 + 原始数值”，不强行跨平台换算。
- 敏感凭证泄露风险：使用系统安全存储，日志脱敏，删除订阅时清理凭证。
- DDE Shell 插件 UI 空间有限：面板只展示摘要，细节放入 popup。

## 12. 待确认事项

- OpenAI API 额度展示应优先显示成本、tokens，还是二者同时展示。
- GLM Coding Plan 的可用查询接口需要在实现阶段再次验证。
- 是否需要在首版支持用户自定义供应商。
